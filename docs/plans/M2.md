## 3. Decisions (agreed 2026-10-29)

| # | Decision | Choice and why |
|---|---|---|
| D1 | Test stack | **Vitest** is the test runner and is built for Vite projects. **jsdom** is a fake browser page so components can render in Node. **React Testing Library** + `@testing-library/user-event` + `@testing-library/jest-dom` let tests render components, type and click like a user, and check what is on screen. **MSW** answers the app's `fetch` calls with fake responses in tests, so tests never touch the real API. Versions are in §4. |
| D2 | Router | **React Router v7 in "declarative mode"** (`BrowserRouter`, `Routes`, `useParams`, `useSearchParams`, `Link`). It is the most common React router. It reads and writes query parameters, and it can choose between replacing the current history entry and adding a new one (`replace`), which D6 needs. We don't use its data loaders, because TanStack Query owns data. v8 is excluded by the Node version (§4). |
| D3 | Data fetching | **TanStack Query v5.** Caching, loading/error states, retries, cancellation and ignoring outdated results are all built in. We only write a few settings and one retry rule. |
| D4 | Search and filter | Load the **species index** once and do search, type intersection and pagination in the browser. Species (not Pokémon) are the list entries, so alternate forms never appear. |
| D5 | Type matchups | **Fixed list of the 18 battle types.** Use current `damage_relations` only. Ignore abilities. The multiplier is calculated from the Pokémon's 1–2 types (0, ¼, ½, 1, 2, 4). No per-Pokémon results are hardcoded. |
| D6 | Search and history | Typing **replaces** the current URL entry. Page changes and type-filter changes **add** a history entry. Back/Forward restore the list state from the URL. |
| D7 | Detail route | `/pokemon/:name` accepts **species names**. Each one resolves to that species' default variety (so `deoxys` → `deoxys-normal`). Unknown names and form names such as `pikachu-gmax` show not-found. |

## 5. PokéAPI facts the plan relies on

**Documented** (https://pokeapi.co/docs/v2):
- Fair use: *"Locally cache resources whenever you request them."* Rate limiting *"has been removed entirely"*, but they ask apps to limit request frequency.
- List endpoints take `limit` and `offset`. The default page is 20. `count` is the total number of resources.
- `Pokemon.is_default`: *"Set for exactly one Pokémon used as the default for each species."* `PokemonSpecies.varieties` lists `{ is_default, pokemon }`.
- `PokemonSpecies.evolution_chain`, `flavor_text_entries` (`flavor_text`, `language`, `version`). The docs say flavour text is unprocessed and contains special characters.
- `ChainLink`: `is_baby`, `species`, `evolution_details`, `evolves_to` (*"A List of chain objects"*), so chains are trees.
- `Type.damage_relations` uses the fields `no_/half_/double_damage_from/_to`. `past_damage_relations` holds older generations. `Type.pokemon` is a list of `{ slot, pokemon }`.

**Observed in live responses on 2026-10-29, not documented as guaranteed:**
- `/pokemon-species?limit=100000` returned all 1025 species in one response. The largest allowed `limit` is not documented.
- For every species id N (1–1025), the Pokémon with id N is that species' default variety. 326 Pokémon have ids above 10000, and those are alternate forms. **The docs don't promise that the ids match.**
- 37 species have a default Pokémon with a different name (`deoxys` → `deoxys-normal`, `giratina` → `giratina-altered`, `shaymin` → `shaymin-land`, …). `/pokemon/deoxys` returns 404, while `/pokemon/386` and `/pokemon-species/deoxys` return 200.
- `/type/fire` lists 109 Pokémon, and 28 of them are alternate forms.
- `/type` lists 21 types: the 18 battle types plus `stellar`, `unknown` and `shadow`. `stellar` and `shadow` have empty `damage_relations` and no Pokémon. D5's fixed list means we don't depend on this.
- Eevee's chain (`/evolution-chain/67`) branches 8 ways at the first step.
- Responses send `cache-control: public, max-age=86400` and `access-control-allow-origin: *`.

**Assumptions the plan depends on:**
- **A1.** "Species id N = default Pokémon id N". This was observed, not documented. Both list cards (which fetch Pokémon by id) and the type filter (which maps type members to species by id) rely on it. The only documented-safe approach, fetching each species first, would double the card requests (≈41 per page) and break the 25-request budget. So we use the shortcut, with these safeguards:
  1. **Runtime check with fallback (S3 + S6).** Every Pokémon response already includes `species.name` (it's in `pokemonSchema`). When a card loads Pokémon id N, it checks that `species.name` equals the species name it expected. If it doesn't, the card ignores that response and takes the documented route instead: `getSpecies(name)` → the `is_default` variety → that Pokémon. While the assumption holds this costs nothing. If it ever breaks, cards still show the correct Pokémon, just with an extra request each.
  2. **Unit tests (S3)** pin the mapping, including `deoxys` ↔ `deoxys-normal` (id 386), and test the fallback.
  3. **Scheduled smoke test (M4, against the real API).** Fetch `/pokemon-species?limit=100000` and `/pokemon?limit=100000` (2 requests) and check that for every species id N, Pokémon id N exists and its name equals the species name or starts with `<species>-`. A failure warns us without blocking merges.
  4. **Remaining exposure:** the type filter maps members by id without a per-entry check. If A1 broke, the filter could include or miss a species, but the cards would still show correct data (safeguard 1), and the smoke test would flag it. Recorded in DECISIONS.

- **Scope:**

  - New schemas in `src/api/schemas.ts` (only the fields we use) for:

### S3: Domain mapping and pure logic (`feat/domain-logic`; may split into S3a mapping / S3b list + URL)
- **Purpose:** brief §3.2 says conversion, cleanup and filtering belong in a mapping layer, not in components. These are pure functions, easy to unit test.
- **Scope** (proposed folder `src/domain/`):
  - Our own types for list entries, Pokémon detail, evolution tree and matchups. Components never see raw API shapes.
  - A1 check: a function that says whether a Pokémon response belongs to the expected species (compares `species.name`). S6 uses it to decide whether to fall back.
  - Units: decimetres → metres, hectograms → kilograms.
  - Flavour text: pick one English entry (rule decided here, e.g. the latest game version) and normalise `\n`, `\f`, soft hyphens and repeated spaces.
  - Evolution chain → tree. Each node has a species name and id (taken from the species URL) and its children.
  - `BATTLE_TYPES`: the fixed list of 18 (D5).
  - Matchups. For each attacking type A in `BATTLE_TYPES`, the multiplier is the product over the Pokémon's types T of: 2 if A is in T's `double_damage_from`, ½ if in `half_damage_from`, 0 if in `no_damage_from`, otherwise 1.
  - List query (D4): (species index, search, chosen type member lists, page) → (entries for this page, total, total pages).
    - Search is a case-insensitive substring match on the name.
    - Type members are mapped to species by id (A1), dropping ids not in the index (alternate forms).
    - Two types → intersection.
    - Page size 20.
  - URL params ↔ list state (§3.5, untrusted input):
    - `page`: positive integer, otherwise 1.
    - `q`: trimmed and length-capped.
    - types: only names in `BATTLE_TYPES`, no duplicates, at most 2, otherwise dropped.
    - Exact param names (e.g. `page`, `q`, `type` repeated) are chosen here.
- **Depends on:** S2 (types and fixtures).
- **Acceptance:** all functions are pure (no fetch, no React) and covered by tests.
- **Tests (unit):**
  - Unit conversion with real values.
  - Flavour-text cleanup with a real `\f` string.
  - Linear, first-step branching and later branching chains.
  - Matchups: single type; dual type with 4× and ¼×; immunity making the result 0×; every result is one of {0, ¼, ½, 1, 2, 4}; exactly 18 entries.
  - List query: partial and mixed-case search; no matches → empty; one type; two types → intersection; alternate-form ids dropped; `deoxys-normal` (id 386) maps to species `deoxys`; page past the end; page boundaries.
  - A1 check: matching species → accepted; mismatched species → rejected.
  - URL parsing: `page=-1`, `page=abc`, `type=stellar`, three types, duplicate types, encoded characters, plus round-tripping.
- **Verify:** `npm test`, `npm run typecheck`.

### S5: Data-fetching layer with TanStack Query (`feat/data-hooks`)
- **Purpose:** caching, retries, cancellation and loading/error states in one place (D3).
- **Scope:**
  - Add `@tanstack/react-query`. Wrap the app in `QueryClientProvider`.
  - One query-key convention, plus one small hook per endpoint (*(proposed)* `src/queries/`). Each hook passes TanStack's `signal` to the client. The TanStack docs say the signal is aborted when a query *"becomes out-of-date or inactive"*, but only if the query function actually uses it.
  - Defaults:
    - **Caching** (brief §3.2: *"returning to a page you have already seen makes **none**"*). Two TanStack settings decide this:
      - `staleTime` controls how long data counts as fresh. Fresh data is reused without refetching.
      - `gcTime` controls how long data that no page is using stays in memory.

      The brief has no time limit, so both are set to `Infinity` for this session. PokéAPI data doesn't change while someone is browsing. The cache holds at most a few thousand small, already-trimmed objects, which is acceptable memory use.

      **Why both matter:** with only a long `staleTime`, the default `gcTime` of 5 minutes would delete a page's data after you left it for 5 minutes, and going back would request it again, breaking the brief's rule.

      Also set `refetchOnWindowFocus`, `refetchOnReconnect` and `refetchOnMount` to `false`. They have no effect on fresh data anyway, but setting them makes the "no refetch" intent obvious.

      The cache lasts for one browser session. After a full page reload, the browser's own HTTP cache (PokéAPI sends `max-age=86400`) may answer instead. Saving the cache across reloads is not required and is not planned.

      **Errors are not cached as data.** A failed query is retried when the view is shown again or retry is pressed.
    - **Retry rule:** retry only `network`, `timeout` and `http` with status ≥ 500. Never retry `not-found`, `invalid-response` or other 4xx. Keep the documented default backoff, `min(1000 * 2 ** attempt, 30000)`, up to 3 retries.
    - **Retry button:** each view's retry button calls the query's `refetch`.
  - **Offline:** TanStack Query's default network mode pauses queries while the browser is offline instead of failing them. Decide here (after reading the TanStack network-mode docs) how offline appears to the user: either a visible "You're offline" state, or a mode that surfaces it as an error with retry. Either way, never an endless spinner.
  - A test helper that renders a component with a fresh `QueryClient` (retries off unless the test is about retries) and a `MemoryRouter`.
- **Depends on:** S2, S4.
- **Acceptance:** components get `{ data, error, isPending, refetch }`-style results and never import the client's `fetch` code or call `fetch`.
- **Tests (MSW):**
  - The same query rendered twice → one request.
  - Unmount, advance fake time past 5 minutes, mount again → **zero** new requests (proves `gcTime` is not the default).
  - Unmounting while pending → the request's signal is aborted.
  - 503 then 200 → succeeds after a retry. Use fake timers or a test override for the delay.
  - 404 → exactly one request (no retry).
  - Invalid body → error, no retry.
  - Error then `refetch` → success.
- **Verify:** `npm test`, `npm run typecheck`.
- **Risk:** check the `staleTime`, `gcTime` and network-mode defaults against the TanStack v5 docs in this step. The plan only relies on the cancellation and retry behaviour checked above.

### S6: List page and pagination in the URL (`feat/pokemon-list`)
- **Purpose:** the §2 Browse requirements.
- **Scope:**
  - The list page reads its state from the URL through the S3 parser, loads the species index, and runs the S3 list query.
  - It renders a grid of cards. Each card loads its Pokémon by id (A1) and shows number, name, official artwork and type names as text.
  - Each card runs the A1 check. On a mismatch it falls back to species → default variety (§5).
  - Labelled previous/next page controls and a "page X of Y" indicator. Changing the page adds a history entry (D6).
  - Images use `loading="lazy"` with fixed width/height (or aspect ratio), so the page doesn't jump while they load. Missing artwork (`null`) shows a placeholder.
  - The layout works from 360px.
- **States:**
  - The index is loading.
  - The index failed (message + retry).
  - A card is loading (a placeholder of the same size).
  - A card failed (small message + retry on that card).
  - A page past the end shows an "out of range" message with a link to page 1.
- **Depends on:** S3, S5.
- **Acceptance:**
  - `/?page=3` shows page 3, and reloading keeps it.
  - Back/Forward move between visited pages.
  - Alternate forms never appear.
  - Revisiting a page fires no network requests (check the Network tab; the measured budget comes in M4).
- **Tests (component, MSW):**
  - Loading state shown first.
  - Index error → retry → list appears.
  - The URL page decides which names are shown.
  - Clicking next updates the URL and the names.
  - Card error + retry.
  - Out-of-range page state.
  - A1 fallback: MSW returns a Pokémon of the wrong species for id N, and the card shows the correct Pokémon from the species route.
- **Verify:** `npm test`, then manual check in `npm run dev` with DevTools at 360px.

### S7: Search (`feat/list-search`)
- **Purpose:** §2 search and §3.1 race-condition proof.
- **Scope:**
  - A labelled search input whose value **comes from the URL `q`**, so the URL is the one source of truth and nothing needs to be kept in sync.
  - Each keystroke writes `q` with `replace` (D6) and resets the page to 1.
  - Filtering is instant because it happens on the loaded index, so the grid always matches the current text.
  - Card requests for Pokémon that are no longer shown become inactive and are cancelled (S5).
- **States:** no matches → *"No Pokémon match '<query>'"*, with the query shown as text, not markup.
- **Depends on:** S6.
- **Acceptance:**
  - Matching is partial and case-insensitive (`PIK` finds pikachu).
  - Reloading keeps `q`.
  - Typing several letters then pressing Back goes to the state *before* the search started (one history entry, not one per letter).
  - Back after a page change restores the earlier query and page.
- **Tests (component, MSW):**
  - Partial and case-insensitive matching.
  - Empty state message.
  - URL updated with `replace` (history length unchanged).
  - **Race test:** make the response for a card that matches only an earlier query slow. Type the next letters. Then check that the older result never appears, the final grid matches only the latest query, and the slow request was aborted.
- **Verify:** `npm test`.
- **Risk:** each keystroke can start up to 20 card requests. Cancellation and caching limit this. If the M4 budget measurement shows a problem, delaying card fetches slightly while typing is the fix. Leave it out of M2 unless measurements call for it.

### S8: Type filter (`feat/list-type-filter`)
- **Purpose:** §2 filter by one or two types.
- **Scope:**
  - Up to 2 types chosen from `BATTLE_TYPES` with labelled, keyboard-usable controls (e.g. checkboxes, with a third choice blocked and explained).
  - Each chosen type is loaded with `getType` (cached and shared with S11). Members are mapped and intersected by the S3 list query.
  - A filter change adds a history entry (D6) and resets the page to 1.
  - Works together with search and pagination.
- **States:**
  - Type data loading.
  - Type request failed (message + retry).
  - No matches for these types (and search) → a message naming the filters.
- **Depends on:** S6, S7.
- **Acceptance:**
  - Two types → only species whose default form has both.
  - A shared URL like `/?type=fire&type=flying&q=char&page=1` restores everything.
  - An invalid or third type in the URL is ignored.
  - Back undoes a filter change.
- **Tests (component, MSW):**
  - One type.
  - Two types → intersection.
  - Combined with search.
  - Type error + retry.
  - Empty intersection message.
  - URL restore.
  - Invalid type ignored.
- **Verify:** `npm test`.
