## 3. Words used in this plan

- **E2E (end-to-end) test:** a robot opens a real browser, clicks through the real app and checks what appears. **Playwright** is the tool that drives the browser.
- **Recorded responses:** real PokéAPI answers saved to files once. In E2E tests the browser gets these files instead of calling the internet, so tests are fast and give the same result every time.
- **Smoke test:** a quick "is it still alive and still shaped the way we expect?" check against the real service.
- **HTTP header:** a short label the server attaches to every response, telling the browser how to treat it.
- **CSP (Content Security Policy):** a header listing the *only* places the browser may load scripts, styles, images and data from. If an attacker manages to sneak markup into the page, the browser still refuses to run it. `unsafe-inline` / `unsafe-eval` are escape hatches that would undo most of that protection, so the brief bans them for scripts.
- **HSTS:** a header telling the browser "only ever talk to this site over HTTPS".
- **Clickjacking / `frame-ancestors`:** another site embedding Dexter invisibly in a frame to trick clicks. `frame-ancestors 'none'` forbids being framed.
- **axe:** an automatic accessibility checker. Violations are graded minor, moderate, serious or critical.
- **Dependabot:** a GitHub feature that warns about known-vulnerable dependencies and opens update PRs.
- **Trivy:** a scanner that lists known vulnerabilities (CVEs) in a container image's system packages, or in a lockfile.
- **CVE:** a public ID for a known security bug.
- **Required check:** a CI job that GitHub won't let a PR merge without.
- **SHA pinning:** referring to a GitHub Action (or image) by the exact fingerprint of its code, so nobody can swap the code behind a version tag.
- **Code-splitting:** cutting the app's JavaScript into per-page pieces, so the browser downloads a page's code only when it's opened.
- **OWASP Top 10:** a widely used list of the 10 most important web-application security risk categories.

## 5. Technical specifications

### 5.1 Header policy (D21). Exact values to verify against MDN in H5

```
Content-Security-Policy:
  default-src 'none';
  script-src 'self';
  style-src 'self';
  img-src 'self' https://raw.githubusercontent.com;
  connect-src https://pokeapi.co;
  base-uri 'none';
  form-action 'none';
  frame-ancestors 'none'
Strict-Transport-Security: max-age=31536000          (no includeSubDomains/preload: we won't own the M5 domain's parent)
X-Content-Type-Options: nosniff
X-Frame-Options: DENY                                (older browsers' version of frame-ancestors)
Referrer-Policy: no-referrer                         (nothing about the page is sent to PokéAPI or GitHub)
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()
```
- What each part means in plain English:
  - `default-src 'none'`: block everything not listed below.
  - `script-src 'self'`: only our own JS files can run.
  - `style-src 'self'`: only our own CSS files.
  - `img-src`: only our own images (the favicon) and the official artwork host.
  - `connect-src`: the app may only fetch data from PokéAPI.
  - `base-uri` and `form-action`: shut down two less obvious injection tricks.
- HSTS is ignored by browsers over plain `http://localhost`, so it's harmless locally and starts working over HTTPS in M5.
- Also: `server_tokens off;` (stops nginx announcing its version number).
- **To verify in H5:**
  - React's `style` prop works under `style-src 'self'` (StatBars).
  - `form-action 'none'` doesn't affect our forms, which never submit to a server. If it does, use `'self'`.
  - The export download (a `blob:` link) still works.
- **M5 dependency (preparation only, not an M4 deliverable):** M5 makes the API base URL configurable when the container starts (§3.4). `connect-src` must then follow that value, probably via nginx's template support. The runtime config must come from a **same-origin file**, never an inline script, or `script-src 'self'` breaks. `SECURITY.md` and the M4 plan record this so M5 doesn't weaken the CSP.

### 5.2 E2E setup (D19, D20)
- **Layout:**
  - `e2e/` (outside `src/`, so Vitest and the app build ignore it)
  - `playwright.config.ts` at the root
  - scripts: `npm run e2e`, `npm run e2e:record`
- **Base URL:** `E2E_BASE_URL`, default `http://localhost:8080`.
  - Locally, Playwright starts the container itself (`docker compose up --build`), waits for `/healthz`, and reuses a container that's already running.
  - In CI the workflow starts the already-built image, and Playwright uses it.
- **Shared test fixture** (`e2e/fixtures.ts`), used by every test:
  1. Answers `https://pokeapi.co/api/v2/**` from `e2e/fixtures/api/`. The file name is worked out from the path and query.
  2. Answers `https://raw.githubusercontent.com/**` with one placeholder PNG.
  3. **Fails the test** on any other outside request, or any PokéAPI request with no recording. This proves CI never touches the live API.
  4. **Fails the test on any CSP violation.** It listens for the browser's `securitypolicyviolation` event and CSP console errors. So *every* journey also proves the CSP doesn't break the app.
  5. Starts each test with empty storage. Playwright gives every test a fresh browser context.
- **Recorder** (`e2e/record.ts`, run by hand, never in CI):
  - It holds a list of the URLs the journeys need, roughly 60–80. It fetches them politely, one at a time, validates each with `src/api/schemas.ts`, and writes the parsed result.
  - Deliberate 404s (e.g. `pokemon-species/pikachuu`) are stored as 404s.
  - `e2e/fixtures/README.md` records the date and the reason for each file, like `src/test/fixtures/README.md`.
- **Data needed:**
  - species index (full, 1025)
  - Pokémon 1–40 (pages 1 and 2)
  - search hits
  - the fire and flying types
  - eevee + its 8 evolutions (species, Pokémon, chain, types)
  - members' types for the team analysis

### 5.4 Smoke test (D27)
- `smoke/*.smoke.ts` + `vitest.smoke.config.ts` (Node environment, no MSW, real `fetch`). Not matched by `npm test`. Script: `npm run smoke`.
- **Checks** (about 10 requests):
  1. Species index parses with our schema, and `count ≥ 1025`.
  2. **A1 id check** (M2 plan §5 item 3): every species id N has a Pokémon id N whose name equals the species name or starts with `<species>-`.
  3. eevee: Pokémon, species and evolution chain parse. The chain branches 8 ways.
  4. `type/fire` parses and still includes alternate forms (ids > 10000), which our filter drops.
  5. `pokemon-species/pikachuu` → our client reports `not-found`.
  6. Artwork URLs still start with `https://raw.githubusercontent.com/`. **If this changes, the CSP `img-src` must change**, so the smoke test guards the CSP too.
- **Workflow** `.github/workflows/smoke.yml`:
  - `schedule` (daily) + `workflow_dispatch`, `permissions: contents: read`
  - not a required check
  - a manual "test the alarm" option: a `workflow_dispatch` input `force_failure` (default off) that makes the run fail on purpose, so the notification path can be tested without breaking anything
- **How we hear about a failure** (checked against GitHub Docs on 2026-11-07, not assumed):
  - *Who:* "Notifications for scheduled workflows are sent to the user who last modified the cron syntax in the workflow file." That means the account that authors the commit adding the `cron:` line, which is yours. Someone who edits other parts of the file doesn't become the recipient.
  - *Whether anything arrives at all* depends on **that person's own setting**: GitHub → Settings → Notifications → System → Actions. The dropdown can be "Don't notify", "On GitHub" or "Email", with an option "Only notify for failed workflows". The docs say this applies to repositories with Actions "that you are watching". **If it's set to "Don't notify", no email comes.** So H9 includes checking it.
  - *Always visible without notifications:* a red run in the repository's Actions tab, and a smoke-test status badge in the README (added in H11).
  - *Inactivity:* "In a public repository, scheduled workflows are automatically disabled when no repository activity has occurred in 60 days." Noted in the test strategy. Re-enabling is one click in the Actions tab, and per GitHub Docs notifications then go to whoever re-enabled it.

- **Purpose:** `dangerouslySetInnerHTML` is React's way to insert raw HTML. If that HTML ever contained user or API text, an attacker could run code in the page (XSS, "cross-site scripting"). We don't use it. This makes sure nobody adds it later.
- **Scope:** `.oxlintrc.json`: `"react/no-danger": "error"`.
- **Outcome:** any use fails `npm run lint`, which fails CI, which blocks the merge.
- **Acceptance:**
  - lint passes on the current code
  - a throwaway file using `dangerouslySetInnerHTML` makes `npm run lint` exit with an error (shown in the PR description, file not committed)
- **Verify:** `npm run lint` both ways.
